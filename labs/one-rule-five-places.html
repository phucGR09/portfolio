DRY (Duplicated Logic)

Code Design Intermediate Expensive

We updated the tax rate everywhere — except the one screen that actually charges the customer.

5 files to change → 1 file to change

Classic problem

The situation

The VAT rate started as one number in the cart's checkout code. When the invoice email needed it too, someone copied the number over — one line, shipped same day. Then the admin report needed it. Then the mobile app. Each copy was a reasonable call in isolation: asking for a shared config felt like over-engineering for a number that "never changes." Then the rate changed, and updating it meant remembering every place that copy had ended up.

Under the hood

In duplicated mode, "deploy" means finding and editing five copies by hand — and the lab always finds one (chosen by a seeded random pick, so it's reproducible, not hand-picked) that gets missed. In single-source mode, the five screens read the rate from one place, so there is nothing to forget: one edit, five correct screens.

The principle

A value that must be the same in five places will eventually be different in one of them. Put the shared fact in one place and have every screen read from it, so a change takes one edit, not five.

Trade-offs & when NOT to

Apply this when

A business fact — a rate, a limit, a feature flag — must be identical everywhere it's used. If two places can legitimately disagree, it isn't this problem.

Don't when

Two blocks of code merely look similar today but change for different reasons. That's not duplication, it's two domain rules that happen to coincide right now — merging them creates coupling, and the two rules will need to diverge later anyway.

Where this bites in practice

Pricing and tax rates, feature flags, API version strings, and "just this one timeout value" are the repeat offenders — anywhere a number got copy-pasted because a shared config felt like overkill for a value that supposedly never changes. The early sign: grep the codebase for the literal value and count more than one hit outside of tests.

Carry it away

  • Before copying a value a second time, ask where it will need to change next, and put it there once.
  • A number used in more than one place is a shared fact, not a coincidence — give it one address.
  • "It's just one value" is the sentence right before "it's just one more place to miss."
  • Two similar-looking blocks aren't necessarily duplicates — check whether they change for the same reason before merging them.
